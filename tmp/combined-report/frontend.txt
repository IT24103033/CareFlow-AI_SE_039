5. Defect, Fix and Retesting 
Defect ID: M2-F01 
Area: Flutter Appointment Availability UI Testing 
Defect: 
The appointment widget test initially failed with a pumpAndSettle timeout while testing the doctor-
selection loading state. 
Cause: 
The test intentionally used a pending Completer for the slot API request. However, the helper 
method used pumpAndSettle(). Since the asynchronous request was intentionally never completed 
at that point, Flutter continued waiting for the application to become idle and eventually timed out. 
Fix: 
The doctor-selection helper was changed to perform only a single pump() after tapping the doctor. 
Tests where the fake API completed immediately were allowed to use pumpAndSettle() separately. 
Retesting: 
The appointment availability test suite was executed again. 
Before Fix: Test timeout/failure during loading-state testing. 

PAGE 9
After Fix: 
• Appointment Availability tests: 12/12 passed 
• Full Flutter suite: 25/25 passed 
Therefore, the defect was successfully fixed and verified through retesting.

8. Testing Limitations 
This tests focus specifically on frontend UI behaviour. 
The React tests use controlled/mocked API behaviour and therefore do not independently prove 
backend or database correctness. 

PAGE 11
The Flutter appointment widget tests use a FakeApiService to simulate API responses. Therefore, 
these tests verify the UI's behaviour for successful, empty, loading and failed API conditions, but they 
do not replace live backend integration testing. 
Backend/API, database, Agentic AI, performance and security testing were handled by the other 
group members and are outside the individual Member 2 testing scope.
